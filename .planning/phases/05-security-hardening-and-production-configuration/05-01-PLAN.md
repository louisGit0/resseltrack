3. **HSTS header (SEC-02, D-02):** Add `header('Strict-Transport-Security: max-age=31536000; includeSubDomains');` to the existing security-headers block, gated on `$isHttps`. No `preload`.

SEC-01 (D-05) and SEC-03 (D-06) are **verification-only — no code change**: the secrets audit is already clean and the CSP `img-src` already covers `https://res.cloudinary.com` (Phase 4). Their coverage is the audit/confirmation task (Task 2), with an optional cosmetic reword of the line-75 CSP comment.

Purpose: A misconfigured redeploy (e.g. forgetting `SESSION_SECURE`) fails loudly with a clear page instead of silently shipping insecure cookies; HSTS documents the app's TLS posture in code; the secrets audit formalizes SEC-01/SEC-03.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel edge proxy → PHP runtime | The proxy sets `X-Forwarded-Proto: https`; PHP reads it as `$_SERVER['HTTP_X_FORWARDED_PROTO']`. This is the production/HTTPS signal — trusted because it originates from Vercel's own edge, not an arbitrary client reaching the function directly. |
| Deployment config (Vercel env vars) → PHP boot | Untrusted-until-validated configuration crosses here; the boot gate is the runtime assertion that prod secrets are safely set before the session starts. |
| PHP response → browser | The HSTS header instructs the browser to pin HTTPS for `max-age`; must NOT be emitted over plain HTTP (RFC 6797). |
| Repository / build artifact → public | Committed files must contain no secret (`.env` gitignored, only the public CA cert committed). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-01 | Tampering | Protocol downgrade / HTTPS stripping on a returning visitor | mitigate | App-level HSTS `max-age=31536000; includeSubDomains` emitted over HTTPS (Task 1, SEC-02); Vercel edge also emits a stronger 2-year platform HSTS — defense-in-depth, RFC 6797 first-header-wins, no conflict. |
| T-5-02 | Elevation of Privilege | Deployment with empty/default DB credentials | mitigate | Boot gate refuses to start when `DB_PASSWORD` is `''` or the dev default `'reselltrack'`, or any of DB_HOST/NAME/USER is empty (Task 1, SEC-04). |
| T-5-03 | Information Disclosure | Session cookie sent over plain HTTP (SESSION_SECURE=0 shipped to prod) | mitigate | Boot gate refuses to start when `SESSION_SECURE !== '1'` — runs BEFORE `Auth::start()` so the insecure cookie is never set (Task 1, SEC-04; ties to Auth.php:24). |
| T-5-04 | Information Disclosure | Committed API key / password / `.env` | mitigate | `.gitignore`+`.vercelignore` exclude `.env`; SEC-01 audit confirms no committed secret and a public-only CA cert (Task 2); gate also enforces non-empty CLOUDINARY_*/DB creds at runtime (Task 1). |
