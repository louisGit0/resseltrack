<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST /products/{id}/rate | untrusted: product id in path, rating in body — crosses into the rate() handler (ownership + CSRF enforced in Plan 09-02) |
| server → rendered detail HTML | stored rating_note reaches the browser; must be escaped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Elevation of Privilege (IDOR) | POST /products/{id}/rate | mitigate | handler re-validates ownership via Product::find($id, Auth::id()) (Plan 09-02); the route here only maps the path |
| T-09-02 | Spoofing (CSRF) | quick-rate form | mitigate | form embeds `Csrf::field()`; rate() calls `Csrf::validate()` first (Plan 09-02) |
| T-09-04 | Tampering (stored XSS) | rating_note shown on detail | mitigate | rendered via `e($product['rating_note'])` |
| T-09-06 | Tampering (no-JS / JS-off bypass) | quick-rate submit | mitigate | native `type=submit` buttons carry the value via the hidden input — no client-trust assumption; server still validates range + ownership |
| T-09-SC | Tampering | composer/npm installs | accept | no dependency changes in this phase — no install tasks |
</threat_model>
