Add `private const` config for timeouts, max body bytes, max image bytes (~1.5 MB), redirect hop cap, and a blocked-IP list containing the cloud-metadata address `169.254.169.254`.

    Public entry `fromUrl(string $url): array` orchestrates: scheme check (only `http`/`https`, host present) → fetch via the private guarded fetcher → on null/blocked/empty return `['ok' => false, 'message' => '<French manual-entry message>']` → else parse → detect currency and convert → optionally fetch+encode the og:image as a data: URI → return `['ok' => true, 'name' => ..., 'price' => ..., 'currency' => ..., 'converted_eur' => ..., 'image_url' => ..., 'message' => ...]`. A blocked/empty/JS-only page (the expected AliExpress case) is NOT an error — return ok:false with the French message, never a throw.

    Public pure method `isPublicIp(string $ip): bool`: return false unless `filter_var($ip, FILTER_VALIDATE_IP, FILTER_FLAG_NO_PRIV_RANGE | FILTER_FLAG_NO_RES_RANGE)` passes AND the IP is not in the blocked-IP const AND does not start with `::ffff:` (IPv4-mapped IPv6 bypass). This is the canonical resolve-then-validate-IP shape (validating the IP, never the hostname string — that is the Lychee CVE bug).

    Public pure method `parse(string $html): array` returning keys `name`, `price`, `currency`, `image_url` (each `?string`): `libxml_use_internal_errors(true)`, `DOMDocument::loadHTML('<?xml encoding="UTF-8">' . $html)` (encoding hint), `libxml_clear_errors()`, then `DOMXPath` queries for `og:title` (fallback `<title>`), `og:price:amount` (fallback `product:price:amount`), `og:price:currency` (fallback `product:price:currency`), `og:image`. Per D-01, FIRST best-effort-attempt any embedded JSON blob (`window.runParams` / `__INIT_DATA__`-style) present in the returned shell, THEN fall back to the Open Graph meta path; trim and null-out empty strings.

    Public pure method `convert(?float $price, ?string $currency, ?float $rate): array` returning keys `price`, `converted_eur`, `needs_verify` (D-04): when price and currency and a non-null rate are present, compute `converted_eur = round($price * $rate, 2)` and `needs_verify = false`; when the currency is unknown OR the rate is null, keep the raw `price`, set `converted_eur = null` and `needs_verify = true` (never silently relabel). The orchestrator obtains the rate via `(new ExchangeRateService())->latest($currency, 'EUR')`.

    Private guarded fetcher `fetch(string $url, int $hops = 3): ?string`: `parse_url`, reject non-http(s)/no-host; resolve the host (`gethostbynamel` for A + `dns_get_record(..., DNS_AAAA)` for AAAA), validate EVERY resolved IP with `isPublicIp` (reject on any failure, `error_log` the reason, return null), pin curl to the first validated IP via `CURLOPT_RESOLVE => ["host:port:ip"]`, set `CURLOPT_FOLLOWLOCATION => false`, `CURLOPT_PROTOCOLS => CURLPROTO_HTTP | CURLPROTO_HTTPS`, `CURLOPT_TIMEOUT => 5`, `CURLOPT_CONNECTTIMEOUT => 3`, `CURLOPT_MAXFILESIZE => <body cap>`, a realistic browser `CURLOPT_USERAGENT`, and `Accept-Language: fr-FR,fr;q=0.9,en;q=0.8`. On a 3xx with hops remaining, read `CURLINFO_REDIRECT_URL` and recurse (re-running the full guard on the new host); on 200 with non-empty body return the body, else null. The optional og:image fetch reuses this SAME guarded fetcher (D-05a — the image URL is attacker-influenceable) with the image size cap before base64-encoding to a `data:` URI.

    Use the existing `ExchangeRateService` for FX (do not hand-roll a second FX call). Do not add any Composer package. Do not edit the CSP.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-supplied URL → server curl | Untrusted host/IP/redirect/og:image crosses into a server-side outbound fetch — the SSRF surface |
| remote HTML → DOMDocument parse | Untrusted markup parsed server-side |
| detected currency/price → FX call | Untrusted scraped values fed to the FX conversion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Information Disclosure / EoP | `fetch()` → cloud metadata `169.254.169.254` | mitigate | `isPublicIp` denies via FILTER_FLAG_NO_PRIV/NO_RES_RANGE PLUS explicit `169.254.169.254` const; validated before curl |
| T-10-02 | Tampering | DNS rebinding (resolve/validate then re-resolve) | mitigate | Pin curl to the validated IP via `CURLOPT_RESOLVE`; curl never re-resolves (closes TOCTOU) |
| T-10-03 | Information Disclosure | Redirect-based SSRF (302 → internal host) | mitigate | `CURLOPT_FOLLOWLOCATION` off; manual redirect re-runs the full guard per hop; `CURLOPT_PROTOCOLS` http/https only; hop cap |
| T-10-04 | Tampering | IPv4-mapped IPv6 bypass (`::ffff:127.0.0.1`) | mitigate | Explicit `::ffff:` prefix denial in `isPublicIp` |
| T-10-05 | Information Disclosure | Attacker-controlled `og:image` → server fetch to internal IP | mitigate | The image fetch reuses the SAME guarded `fetch()` + size cap before base64 (D-05a) |
| T-10-08 | Denial of Service | Huge response / slow loris | mitigate | `CURLOPT_TIMEOUT` 5s, `CURLOPT_CONNECTTIMEOUT` 3s, `CURLOPT_MAXFILESIZE` body+image caps, redirect hop cap |

Supply-chain (T-10-SC): N/A — this phase installs ZERO Composer packages; all logic uses bundled PHP extensions (curl, dom, libxml, mbstring, filter, json). No install step, so no legitimacy gate applies.
