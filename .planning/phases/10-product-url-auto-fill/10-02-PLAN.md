## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /products/fetch-url | State-triggering POST crossing into the server (CSRF surface) |
| scraped title/price → form fields | Untrusted scraped data injected into form values client-side (XSS surface) |
| user URL → server fetch | Delegated to the SSRF guard in Plan 10-01 (mitigated there) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06 | Spoofing | POST /products/fetch-url | mitigate | `Csrf::validate()` first line of fetchUrl() reads form-encoded `$_POST['_csrf']`; JS posts `application/x-www-form-urlencoded` (a JSON body → 419, by design) |
| T-10-07 | Tampering (XSS) | scraped title flowing into the form | mitigate | JS assigns via `.value`/`.src` (not innerHTML); any server-side echo uses `e()`; image is a `data:` URI, never an external `<img src>` |
| T-10-SH | EoP | route shadowing `/products/fetch-url` by `/products/{id}` | mitigate | Register the static route before the parameterized `{id}` route (Pitfall 1) — verified by the line-order acceptance check |
| T-10-01..05 | (SSRF family) | server fetch | mitigate (Plan 10-01) | The SSRF guard lives in ProductImportService — see 10-01-PLAN threat_model; this plan only delegates to it |
