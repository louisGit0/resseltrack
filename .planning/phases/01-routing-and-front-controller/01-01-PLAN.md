<objective>
Create the four Vercel configuration files that make ResellTrack reachable on Vercel serverless without modifying any existing application code: the PHP function entry wrapper (`api/index.php`), its runtime settings (`api/php.ini`), the routing + runtime config (`vercel.json`), and the deployment bundle exclusion list (`.vercelignore`).

Purpose: Replace Apache `.htaccess` rewriting (Docker dev only) with Vercel `rewrites` so all dynamic routes reach the PHP front controller while the CDN serves static CSS/JS directly. This enables DEPLOY-01 (routes reach PHP) and DEPLOY-02 (assets via CDN), and preserves DEPLOY-03 by leaving `public/index.php` and `public/.htaccess` untouched (D-01).

Output: `api/index.php`, `api/php.ini`, `vercel.json`, `.vercelignore` at the paths shown. Zero changes to existing PHP, views, or Docker files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo → Vercel deployment bundle | Files copied into the deploy bundle cross into a publicly reachable serverless environment; secrets must not cross |
| Vercel CDN → public internet | Static files in `public/` become publicly fetchable |

This phase introduces no new auth, input-validation, or data-handling surface — `public/index.php` (which owns sessions, CSRF, security headers, validation) is unchanged. The only artifacts are config files. No high-severity threats expected for a config-only phase.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-01 | Information Disclosure | `.env` reaching the deploy bundle | mitigate | `.env` already gitignored; `.vercelignore` lists `.env` and `.env.example` (belt-and-suspenders). Acceptance criteria assert both entries present. |
| T-1-02 | Information Disclosure | `public/.htaccess` readable via CDN | accept | Contains only Apache rewrite rules (no secrets). Vercel does not serve dotfiles from the static CDN by default (RESEARCH A3). Low value, low risk. |
| T-1-03 | Tampering | `vendor/` shipped with unexpected contents | accept | `/vendor` excluded from bundle; app needs no Composer runtime deps (self-contained autoloader). No vendor in bundle = nothing to tamper. |
| T-1-SC | Tampering | npm/composer package installs | accept | Phase 1 installs NO local packages. `vercel-php@0.7.4` is referenced by name in `vercel.json` and resolved by Vercel's build system (Vercel-managed), not installed locally — no slopcheck/legitimacy checkpoint required (RESEARCH Package Legitimacy Audit). |

Deferred (NOT Phase 1 blockers, per CONTEXT/RESEARCH): HSTS (SEC-02, Phase 5), `SESSION_SECURE=1` (Phase 3), CSP for R2 domain (SEC-03, Phase 5).
