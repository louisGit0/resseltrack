## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Vercel Lambda → Aiven sessions table | Live session reads/writes over verified TLS; the table must exist before any write() |
| Browser → production HTTPS | The `Secure` flag must be active so the cookie is never sent over plaintext |
| Operator CLI → Aiven MySQL | One-shot idempotent migration re-run from the operator's machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-06 | Denial of Service (broken auth) | sessions table absent at runtime | mitigate | Task 1 re-runs `bin/migrate.php` to create the table BEFORE relying on live sessions; Task 2 log check would surface a "table doesn't exist" / write() PDO error (RESEARCH "Environment Availability"). |
| T-3-07 | Spoofing / Information Disclosure | cookie sent over plaintext (missing Secure) | mitigate | `SESSION_SECURE=1` set in Vercel Production (Task 1, D-10); Task 2 SESS-03 check asserts the `Secure` flag on the live cookie. |
| T-3-08 | Tampering | CSRF 419 regression on the new store | mitigate | Task 2 SESS-04 asserts a real POST returns no 419 — proving `$_SESSION['_csrf_token']` persists across requests (D-07). |
| T-3-09 | Elevation of Privilege | stale session usable after logout | mitigate | Task 2 logout check asserts a protected route redirects to `/login` after logout — `destroy()` removed the row. |

</threat_model>
